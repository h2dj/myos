# Notion 표본 가져오기 (INT-01 1차)

설정 → **Notion 파일 가져오기**(`/settings/notion`)에서 현재 공간 소유자가 사용한다. 파일을 읽고 속성을 선택한 뒤 **매핑 미리보기**를 누른다. 변환 값·오류·관계를 확인하고 최대 10행을 선택해 저장한다. 미리보기는 데이터를 저장하지 않는다. 파일·종류·매핑을 바꾸면 이전 미리보기와 확인 상태를 비운다.

## 지원 파일과 준비

UTF-8 CSV 또는 JSON(객체 배열 / Notion API의 page `results` 목록), 최대 256KiB·200행을 지원한다. CSV는 첫 행의 속성명, 쉼표, 인용된 줄바꿈과 `""` 이스케이프를 지원한다. ZIP·Markdown·XLSX 및 Notion API 직접 연결은 이번 범위에 포함하지 않는다. Notion API JSON의 페이지 본문 블록은 가져오지 않으며 속성에 있는 메모/설명만 매핑한다. 원본 페이지의 나머지 속성은 보존한다.

**Notion 페이지 ID 또는 페이지 URL 열이 반드시 필요하다.** CSV에 이 값이 없으면 원본에서 ID/URL 열을 추가해야 한다. 이름이나 행 번호로 ID를 만들어 중복을 추정하지 않는다. 32자리 ID·하이픈 UUID·`https://…notion.so/…` / `https://…notion.site/…` 페이지 URL을 동일한 소스 ID로 정규화한다. 파일 이름의 DB ID는 개별 페이지 ID를 대신할 수 없다.

JSON 예시(속성명은 화면에서 다시 매핑할 수 있다):

```json
[
  {
    "id": "11111111-1111-4111-8111-111111111111",
    "이름": "과거 완료 기록",
    "완료": true,
    "완료일": "2026-10-20",
    "예정일": "2026-10-20",
    "태그": ["P2", "오늘", "업무"],
    "메모": "원본 완료일을 유지합니다."
  }
]
```

화면의 예제 CSV에는 실제 업무와 관계없는 가상 페이지 ID를 사용한다. 실제 개인 ToDo·사무국 ToDo의 파일·속성명·표본은 아직 제공되지 않아 합성 CSV와 Notion page JSON으로 검증했다. 실제 파일로 미리보기를 확인한 뒤 표본을 가져와야 한다. 두 DB는 **각각 올바른 공간을 선택한 상태에서** 별도로 가져온다. 새로운 공간 생성이나 이름 기반 자동 공간 매핑은 수행하지 않는다.

## 변환과 관계

| 항목             | 동작                                                                                                                                           |
| ---------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| 할 일            | 제목, 설명, 상태/완료 체크, 완료일, 예정 기간, 마감, 우선순위, 태그, 프로젝트·활동·활동처                                                      |
| 프로젝트         | 이름, 설명, 상위 프로젝트. 프로젝트 자체의 기간·상태는 이번 표본 매핑에서 지원하지 않으며 기본 상태 active로 생성                              |
| 상시 사업·활동   | 이름, 설명, 기본 활동처. 기한 없음                                                                                                             |
| 활동처           | 이름, 설명                                                                                                                                     |
| 생성·수정 일시   | 원본 생성 일시는 항목 created_at, 원본 수정 일시는 external_refs.source_updated_at에 보존. MyOS updated_at은 실제 저장 시각                    |
| P1/P2/P3         | high/medium/low로 변환하고 일반 태그에서 제외. 복수 우선순위나 명시적 우선순위와 충돌하면 오류                                                 |
| 오늘 / 포기·못함 | 오늘 태그 제외. 포기·못함은 cancelled로 변환. 완료와 충돌하면 오류                                                                             |
| 상태             | todo/in_progress/done/cancelled 및 기본 Notion 영문·일부 한글 상태 지원. 알 수 없는 값은 오류로 표시하고 파일에서 정리하도록 안내              |
| 날짜             | 유효한 YYYY-MM-DD는 사용자 시간대 기준 종일. 시각은 오프셋/Z가 포함된 ISO 8601. 종료일·마감일의 날짜 전용 값은 해당 날짜 끝까지 포함(DST 반영) |
| 완료일 미상      | done 상태를 유지하되 completed_at=null로 저장하고 미리보기에 안내. 오늘 완료로 추정하지 않음                                                   |

관계 열은 **연결 대상의 Notion 페이지 ID**이다. 같은 공간에 먼저 가져온 이력을 통해 MyOS ID를 찾는다. 다른 공간의 이력·삭제된 대상·다른 종류의 대상은 연결하지 않는다. 관계가 둘 이상인 행은 현재 단일 연결 모델과 맞지 않으므로 오류로 표시한다. 이름만 같은 기존 MyOS 항목과 자동 병합하지 않는다.

권장 순서는 **활동처 → 상시 활동**, **상위/하위 프로젝트 → 할 일**이다. 같은 파일의 부모·자식 프로젝트는 함께 선택하면 파일 순서와 관계없이 부모부터 생성한다. 순환은 차단한다. 표본에서 부모를 선택하지 않으면 해당 자식의 저장이 실패하며, 부모를 먼저 또는 함께 선택해 재시도할 수 있다. 활동의 기본 활동처를 할 일에 자동 상속하지 않으므로 할 일의 활동처가 필요하면 그 열도 매핑한다.

## 중복·변경·오류

`external_refs`의 `(workspace_id, provider, external_id)` UNIQUE와 공간별 트랜잭션 잠금으로 동시 재시도를 직렬화한다. 항목 생성·태그·감사 이력·원본 이력은 행별 저장점 안에서 함께 저장한다. 검증에 실패한 행은 건너뛰고 결과에 사유를 남긴다. 예상하지 못한 DB 오류는 요청 전체를 롤백하므로 재시도할 수 있다.

동일 원본은 **중복 건너뛰기**로 표시한다. 원본 속성이나 매핑·시간대가 달라진 원본은 **변경됨**으로 표시하고 기존 MyOS 내용을 덮어쓰지 않는다. 수정 동기화·중복 이력 해제·자동 병합은 후속 기능이다. 성공 후 미리보기를 갱신하며, 다시 미리보기를 실행해 다음 신규 표본을 선택할 수 있다.

원본 행 속성과 사용한 매핑·시간대·수정 일시·해시는 DB에 보존한다. 원본 파일의 바이트·인용 형식이나 파일 이름을 보관하는 기능은 아니다. 대상이 휴지통 또는 영구 삭제되어도 재생성을 막기 위해 이력과 원본을 유지한다. 가져온 원본에는 업무 내용이 포함되며 공간 소유자의 백업에도 포함된다. 원본 내용·ID·SQL·파일을 서버 성능 로그에 출력하지 않는다.

백업은 v2로 확장했고 v1도 계속 검증·복원한다. 복원 리허설은 가져오기 이력의 개수·체크섬과 복원 후 재가져오기 중복 0건도 확인한다. 일반 운영 DB에 파일을 덮어쓰는 복원 기능은 제공하지 않는다.

## 검증과 배포

- 파서·실제 형태의 Notion page 속성·특수문자·잘못된 날짜·시간대/DST·태그 변환
- 미리보기 무변경, 완료일·생성일 보존, 부모 순서/순환, 누락 관계·재시도·부분 실패
- 동시 재시도, 변경 원본 보호, 삭제 후 재생성 방지, 다른 공간·조회자·편집자 차단
- 모바일/데스크톱 미리보기·저장·중복 표시·매핑 변경 시 초기화, 백업 원본 포함
- 마이그레이션 0006: external_refs와 UNIQUE 추가, RLS 활성화 및 anon/authenticated 직접 접근 회수. 기존 테이블 변경 없음

실제 Notion 파일과 표본 저장 결과를 확인한 다음에 대량/백그라운드 가져오기, 변경분 비교·선택적 갱신, API 직접 연결을 설계한다. 공유 공간 전환 UI는 기존 로드맵의 다음 독립 개발 단계이다.
