# 재정 관리 기본 기능

주 메뉴 **재정 관리**에서 사용하는 개인 전용 원화 수동 가계부입니다. 은행·카드 API 연결, 다중 통화, 투자 자산 평가, 이자 계산, 반복 거래 자동 생성은 포함하지 않습니다.

## 시작하기

1. **계좌 추가**로 은행·현금·신용카드를 등록합니다. 기초 잔액은 거래 기록을 시작하기 직전의 잔액입니다. 카드 미결제액은 음수로 입력합니다.
2. **거래 추가**에서 수입·지출·이체, 거래일, 양수 금액, 계좌, 카테고리, 메모를 입력합니다. 금액은 쉼표·소수점 없이 원 단위로 최대 15자리입니다. 실제 기록용이므로 미래 거래일은 허용하지 않습니다.
3. 카드 사용은 카드 계좌의 **지출**로 기록합니다. 카드 대금 납부는 은행 → 카드 계좌 **이체**로 기록하면 지출을 두 번 계산하지 않습니다.
4. 조회 월을 바꾸면 해당 월의 수입·지출·순수입, 카테고리별 지출과 예산을 봅니다. 거래는 50건씩 페이지로 표시하고 요약은 월 전체를 집계합니다.
5. **예산 추가**에서 월·카테고리·한도를 지정합니다. 카테고리 이름은 거래와 정확히 일치해야 하며 직접 만든 이름도 사용할 수 있습니다. 같은 월·카테고리를 저장하면 기존 예산을 수정합니다. 0원 한도도 허용합니다.

## 잔액과 집계

- 은행·현금·카드 모두 `기초 잔액 + 수입 − 지출 + 들어온 이체 − 나간 이체`로 잔액을 계산합니다.
- 계좌 합산 잔액은 **현재 전체 기록** 기준이며, 선택 월 말의 과거 잔액이 아닙니다. 보관 계좌와 카드의 음수 잔액도 포함합니다. 모든 자산을 평가한 순자산 지표는 아닙니다.
- 월 순수입 = 해당 월 수입 − 지출입니다. 기초 잔액·이체는 수입과 지출에 넣지 않습니다.
- 월 범위는 사용자가 입력한 거래 날짜의 첫날부터 다음 월 첫날 직전까지입니다. 시간대에 따른 UTC 변환을 하지 않는 날짜 값입니다. 기본 월과 오늘은 사용자 프로필 시간대를 따릅니다.
- 원화는 DB의 정수 정밀도 numeric와 BigInt로 계산하며 계좌가 많아 합산이 JavaScript의 안전한 정수 범위를 넘어도 금액을 보존합니다.

## 수정·보관·휴지통

계좌 이름·종류·기초 잔액을 수정할 수 있습니다. 기초 잔액을 고치면 현재 잔액도 바뀝니다. **보관**은 계좌를 새 거래 선택지에서 제외하지만 과거 거래와 잔액은 유지합니다. 사용 재개도 가능합니다.

거래 수정은 계좌 잔액·월별 집계·예산에 즉시 반영합니다. 삭제한 거래는 해당 월 **휴지통 보기**에서 복원합니다. 삭제 중에는 모든 잔액과 집계에서 빠지며, 복원·동일 저장 요청 재시도 때 중복 합산하지 않습니다. 기존 거래가 연결된 보관 계좌는 그 거래를 수정할 때만 유지할 수 있습니다. 예산 삭제는 거래 내역에 영향을 주지 않습니다.

## 개인 정보·백업

재정은 선택한 공유 공간과 관계없이 본인의 개인 공간에서만 사용합니다. 공간의 조회자·편집자·다른 사용자에게 계좌·거래·예산을 공개하지 않습니다. 공유 대시보드 KPI와 공유 공간 백업에도 포함하지 않습니다. 감사 로그에는 작업 종류와 레코드 ID만 저장합니다.

마이그레이션 **0008**은 `finance_accounts`, `finance_entries`, `finance_budgets`와 두 개의 분류 enum, FK·인덱스를 추가합니다. 세 테이블의 RLS를 활성화하고 anon/authenticated 직접 접근을 회수합니다. 기존 테이블의 데이터는 변경하지 않습니다. 운영 적용을 먼저 완료한 뒤 웹 변경을 병합합니다.

워크스페이스 백업 **v5**는 소유자의 개인 공간에서만 재정 테이블을 포함하며 보관 계좌·삭제된 거래도 보존합니다. v1~v4 백업 검증·복원도 지원합니다. 검증용 별도 DB에서 레코드 체크섬과 재정 잔액·지출을 비교합니다.

## 설명과 추가 메모

계좌·예산 등록/수정에서 용도와 사용 기준을 기본 설명으로 저장합니다. 각 카드의 **추가 메모**에서는 날짜별 보충 내용을 여러 개 남기고 수정·삭제할 수 있습니다. 보관 계좌에서도 사용할 수 있으며, 예산을 삭제하면 그 예산의 메모도 함께 정리됩니다. 자세한 연결·메모 기능은 [관련 항목과 추가 메모](relationships-and-notes.md)를 참고하세요.

## 고정 지출과 수지 예측

`/finance/planning`에서 월·분기(3개월)·연 고정 지출과 한 번 또는 반복되는 예정 수입·지출·이체를 등록한다. 첫 예정일을 기준으로 반복하며, 없는 날짜는 해당 월 말일로 계산한다. 1월 31일의 다음 회차는 2월 말일, 그다음은 3월 31일이다.

예측은 현재 전체 계좌 순잔액에 오늘부터 기준일까지의 미확정 예정 수입에서 지출을 뺀 값을 더한다. 앞으로 1주(7일 후), 1개월(달력 기준), 월말·분기말·연말 또는 직접 입력 날짜를 선택한다. 양 끝 날짜를 포함한다. 계좌별 예상 잔액, 일별 마감 추이와 최저 잔액도 표시한다. 카드 부채는 음수 잔액이며 이체는 전체 수지에 영향을 주지 않는다. 등록되지 않은 변동 지출과 하루 안에서의 입출금 순서는 예측하지 않는다.

실제 지급·수령 시 회차를 확정하면 거래를 만들고 해당 회차를 예정 합계에서 제외한다. 같은 회차를 재시도해도 한 거래만 생성한다. 확정 거래가 삭제된 경우 원래 거래를 복원한다. 원래 거래의 실제 금액·계좌를 사용하므로 이후 예정 규칙 수정으로 과거 실적이 바뀌지 않는다. 직접 입력한 거래는 자동 연결하지 않으므로 대응하는 회차를 제외해야 한다. 이미 확정·제외된 회차가 있으면 첫 예정일과 반복 주기를 변경할 수 없다.

지난 미처리 회차는 미래 예측에 넣지 않으며 규칙의 거래 확정으로 처리할 수 있다. 중지한 규칙은 예측에서 빠진다. 실제 거래일은 사용자 시간대의 오늘까지 허용한다. 보관된 계좌로 새 거래를 확정하려면 계좌를 다시 사용하거나 예정 계좌를 변경한다.

계산 범위는 오늘부터 최대 10년(2099년까지), 활성 규칙 1,000개, 계산 회차 10,000개이다. 초과 시 일부 결과로 오인하지 않도록 오류를 표시한다. 모든 금액 계산은 정수 원화로 처리한다. 백업 v6은 규칙과 회차별 처리·거래 연결을 포함하며 v1~v5 복원을 계속 지원한다.
